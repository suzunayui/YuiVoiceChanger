# YuiVoiceChanger

BeatriceモデルをGPUまたはCPUで直接動かす、ローカルのリアルタイムボイスチェンジャーです。
Electron / Reactの画面とPython 3.15の音声処理を組み合わせています。

## 必要な環境

- Windows x64、またはmacOS 14以降のApple Silicon Mac。Windowsは対応NVIDIA GPUまたはCPU、Mac試用版はCPUで変換します。[Mac版の導入](docs/mac-preview.md)。
- Beatrice 2.0.0-rc.0形式の`.toml`と5つの`.bin`、または学習チェックポイント（`.pt.gz` / `.pt`）。声IDは0です。
- 初回セットアップ用のネット接続と、数GB以上の空き容量。

VST・Pedalboardは使用しません。`.bin`を選んだ場合、同じフォルダにある1つの`.toml`を探します。複数ある場合は`.toml`を直接選んでください。
RVCの`.pth`・`.onnx`を選ぶと「モデルを追加」へ進み、GPUでこのアプリ用のモデルを学習できます。学習済みの重みは同梱しません。

## 使い方

1. 「環境設定」の「必要な環境を自動セットアップ」を押します。変換環境が未設定の場合は、起動時に環境設定を開きます。
2. 「声を変える」の「モデル一覧」から、お持ちのモデルを追加するか、「つくよみちゃんで試す」を開いて公式モデルを導入します。候補を選び、「このモデルに切り替える」で確定します。RVCから追加する場合は下記の学習手順へ進みます。
3. 「声を変える」でマイクと出力先を選択し、開始します。

OBSや通話へ送る場合は、[VB-CABLE](https://vb-audio.com/Cable/)を用意し、出力をCABLE Input、送信先アプリのマイクをCABLE Outputにします。
初期値は音高+14半音・フォルマント0・入力ゲイン+12dB・出力ゲイン0dBです。
「モデル一覧」内の「つくよみちゃんで試す」に導入ボタンがあります。このボタンは[公式モデルの利用規約](https://prj-beatrice.com/2.0.0-rc.0-official-model-1-terms)への同意を兼ねます。クリック後に公式配布元から約19MBをダウンロードし、コーパス版の声ID 1を一覧に追加します。使用中のモデルは変えず、「このモデルに切り替える」で確定します。導入の進捗・中止・エラーも同じ一覧内に表示します。モデルや画像をアプリに同梱・再配布するものではありません。元のモデルファイルは残し、マイクは自動開始しません。
公式の導入ボタンから追加すると、表示名を「つくよみちゃん」にし、配布物内の`tsukuyomichan.png`をアイコンに自動設定します。別名やアイコンが空の場合は再導入でも補完します。自分で設定したアイコンと別名は保持します。元のモデルファイル名は変更しません。
変換開始まではマイクを開きません。[詳細な設定](docs/beatrice.md)。

画面は操作と状態の表示を中心にしています。右上の音声モニターに、入力レベル・入力から出力までの遅延の目安・変換の実行先をまとめています。ボタン・入出力先・声の調整・CPU/GPU選択にカーソルを合わせると、短い説明がツールチップで表示されます。左メニューの「使い方」では、このREADMEをアプリ内で読めます。詳しい設定やライセンスも同じ画面で表示し、公式サイトなどの外部リンクはブラウザーで開きます。
「環境設定」には変換環境の自動セットアップとCPU/GPU選択をまとめています。使用中のPythonのパスは自動セットアップの下に表示します。CPU/GPU選択は自動保存され、次の変換開始から反映します。モデルの操作はメイン画面の「モデル一覧」で行います。
音声モニターの実行先には、待機中も現在の設定で使う予定のCPU・GPU名を表示します。変換開始後は実際の実行先を表示し、自動選択でCPUへ切り替わった場合も反映します。
ファイルの「参照」は、設定中のファイルがあるフォルダから開きます。設定先が見つからない場合は、存在する親フォルダから開きます。
「声を変える」の「プリセット」直下にある「設定の保存・読み込み」から、設定JSONをエクスポート／インポートできます。モデル本体は含まないため、別のPCではモデル・Python・音声デバイスを選び直します。
お持ちのモデルを読み込むと、初回は拡張子を含むファイル名を表示します。パスや学習元・モデル内の名前から表示名を推測しません。「編集」で画面用の別名とアイコンを変更できます。別名は80文字以内です。「ファイル名に戻す」を押して保存すると別名を解除できます。以前の版で自動生成した表示名は引き継ぎません。
モデルの操作はメイン画面の「モデル一覧」にまとめています。ファイルの追加・モデルの選択・別名やアイコンの編集・一覧からの削除を行えます。一覧での追加やモデル名のクリックでは使用中のモデルを変えません。候補を選び、「このモデルに切り替える」を押したときに確認・切り替えを行います。検索もできます。編集は「保存」で反映し、「キャンセル」では元の設定を保ちます。
「一覧から削除」はモデル名を表示する確認画面を出し、確定後に登録情報だけを外します。モデルや元の画像のファイルは削除しません。使用中のモデルを外すと未選択になります。登録数が10件を超えても自動で消しません。「RVCから作成」から学習画面へ進めます。
メイン画面には使用中のモデルを表示し、モデルの選択と切り替えは「モデル一覧」にまとめています。一覧で候補を選び、「このモデルに切り替える」で実行します。使用中と選択中の候補は区別して表示します。画像未設定のモデルは名前の先頭文字を表示します。モデルの保存先・別名・アイコン・声の番号を保存し、再起動後も引き継ぎます。切り替えは変換を停止してから行い、音の高さや音量は現在の設定を使います。移動・削除されたファイルは選べません。一覧は`%USERPROFILE%\.YuiVoiceChanger\model-history.json`に保存し、設定のエクスポートには含めません。
モデル名の左の画像ボタンから、モデルごとのアイコンを設定・変更できます。対応形式はICO・PNG・JPG・JPEG（20MB以下）です。選んだ画像は小さなPNGとして`%USERPROFILE%\.YuiVoiceChanger\model-icons`へ保存し、元の画像を移動しても表示できます。元の画像は変更しません。アイコンにカーソルを合わせたときに出る「×」で解除できます。アイコンの指定も履歴・再起動後に復元します。設定JSONには画像本体を含まないため、別のPCでは画像を選び直してください。

## 声と音量の調整

「音声のルート」の下にある「プリセット」から、現在の設定に名前を付けて保存できます（1〜80文字）。モデル・声の番号・別名・アイコン、マイクと出力先、ピッチ・フォルマント・入力／出力ゲイン、CPU／GPU、固定遅延・エフェクト・OBS連携設定をまとめて保存します。Python環境・学習設定・OBSのパスワード・モデル本体は含みません。
保存したプリセットは名前付きのボタンで並び、名前をワンクリックすると設定を復元します。変換中も切り替えられます。ピッチ・ゲイン・エフェクトだけの変更は変換を続けたまま反映し、別名・アイコン・OBS設定だけの違いでも音声処理を再起動しません。
会話用と歌枠用で固定遅延を切り替える場合や音声デバイスを変更する場合は、同じモデル・声の番号・CPU/GPUであれば、読み込み済みの重みと測定済みの更新間隔を保持します。Pythonプロセスの起動、モデルの読み込み、ウォームアップを省き、音声ストリームとバッファだけを作り直して再開します。出力タイミングが変わる際の音の空きは残ります。モデル・声の番号・実行先が変わった場合や、モデルファイルが更新された場合はモデルを読み直します。待機中の適用では変換を自動開始しません。
通常の変換停止後も、直近1つのモデルをメモリ（GPU使用時はVRAM）に保持して次の開始に再利用します。アプリ終了、環境セットアップ、自動遅延測定の準備時には音声プロセスを終了して解放します。異なるモデルの重みを複数保持するものではありません。
デバイス番号が変わった場合は保存した名前で照合します。モデルやデバイスが見つからなければ、動作中の変換と設定を保ってエラーを表示します。再起動中の読み込みに失敗した場合は元の設定へ戻して変換の再開を試み、復帰にも失敗すれば停止してエラーを表示します。切り替え中に「停止する」を押すと中止し、その後に自動で再開しません。切り替え中は他の設定変更をロックします。
適用に成功したプリセットは色とチェックマークで表示し、再起動後も現在の設定と一致していれば引き継ぎます。手動調整などで保存内容と一致しなくなった場合は選択色を外します。各ボタン右の鉛筆マークでは名前の変更、現在の設定で上書き、削除ができます。鉛筆マークでは設定を切り替えません。上書きと削除には確認画面があります。同じ名前での新規保存は行いません。
プリセットは`%USERPROFILE%\.YuiVoiceChanger\presets.json`に保存し、再起動後も残ります。通常の設定JSONのインポート／エクスポートにはプリセット一覧を含みません。

- 音の高さ（ピッチ）：声の音程を半音単位で変えます。
- 声の響き（フォルマント）：音程とは別に声の響きや太さを調整します。初期値は0です。
- 入力ゲイン：変換する前のマイク音量です。
- 出力ゲイン：変換後の声の音量です。音割れが表示された場合は下げてください。

ピッチ・フォルマント・入力／出力ゲインは変換中も調整できます。次の音声ブロックから反映し、モデルの読み直しや出力タイミングの変更は行いません。ゲインは10msの短い遷移で切り替えます。モデル・マイク・出力先・CPU/GPUの変更は変換を停止してから行います。スピーカーに出した声をマイクが拾うとハウリングするため、試聴にはヘッドホンを使ってください。
数値の左右の「−」「＋」ボタンでも1ずつ調整できます。フォルマントのスライダーと矢印キーは従来どおり0.5半音刻みです。

## 歌枠用設定

左メニューの「声を変える」と「環境設定」の間にあります。設定は自動保存され、設定JSONのインポート／エクスポートにも含まれます。初期状態では固定遅延とエフェクトを無効にして、従来の音を保ちます。

「固定遅延」の数値は、自動測定の補正を含めた合計です。従来の設定が380ms＋補正139msなら、画面には519msだけを表示します。伴奏と選択した映像はすべてこの値へ合わせます。自動測定の結果表示も合計値で、別の補正欄やOBS側の重複した合計表示はありません。停止中に1ms単位で変更できます。

音声を二重に遅らせないよう、アプリ内の出力予約と、OBSまでの経路で測定された補正は内部では分けて保持します。従来の設定・プリセットを開いても、実際の音声タイミングは変えません。表示値を変更すると、測定済みの補正を差し引いてアプリ内の予約時間を調整します。画面で手動設定できる合計値は200〜3000msです。手動操作では古い補正値にかかわらず合計値を上書きします。起動時には処理速度と音声デバイスの申告遅延から必要な予約時間を確認します。OBSで実測した経路差がある場合は、合計の目標からその差を引いて、声の出力時刻も変更します（OBSまで139msの経路差なら、目標500msに対するアプリ内の予約は361ms）。古い未検証の補正値は下限へ加算しません。旧形式の設定では、変換開始時にその値を除外して新形式へ引き継ぎます。旧形式のアプリ内待ち時間も処理に足りない場合は、必要最小時間に100msの余裕を足して自動で修復します。自動測定も短すぎる設定から開始できるように同じ準備を行います。未測定の場合は経路差を0として扱います。モデル・実行先・音声デバイス・OBSの接続先や伴奏ソースを変更した場合と、設定を別のPCへインポートした場合は、以前の経路測定を再利用しません。処理に必要な最小値にも満たない場合は、その最小値を表示して開始を中止します。固定遅延では出力予約時刻と切り出し位置を固定し、間に合わなかった音を破棄して後続の時刻をずらしません。

伴奏をミックスしない歌枠モードの「処理時間から設定」は変換を停止してから使います。声のモデル・マイク・出力先・CPU/GPU・エフェクトを選んだ状態で押し、準備後の案内に合わせてマイクへ6秒ほどしゃべってください。入力レベルと残り秒数を表示し、採取した音声を現在の設定で変換して処理時間を測ります。最長の処理時間に余裕を持たせ、モデルとデバイスの申告遅延も含めて目標を推定します。その計算結果にさらに100msを加え、固定遅延を有効にして保存します（従来の計算が280msなら380ms）。加算後に上限2000msを超える場合は設定を変更せずエラーを表示します。手動設定や既存プリセットには自動加算しません。既存の設定に反映するには、自動設定をもう一度実行してください。

測定中の音声はメモリ内だけで扱い、ファイルへ保存せず、選択した出力先やOBSへ再生しません。無音・音声不足・デバイスの途切れ・処理速度不足では設定を変更しません。「中止する」やEscで中止できます。測定中は他の設定や変換開始をロックします。これは安定動作に必要な処理時間の推定で、マイクからOBSまで音を戻して測った実測値ではありません。PCの負荷、モデル、デバイス、エフェクトを変えた場合は再測定してください。

固定するのはアプリ内の音声サンプルの時刻です。目標値は音響的な実測値ではなく、機器の誤差や配信ソフト以降の遅延までは保証しません。通常の波形整列は音質に合わせて位置を探索します。固定遅延では切り出し位置を動かさず、モデルが使う周期音の位相とノイズを前の推論窓から引き継ぎます。継ぎ目の打ち消しによる周期的な音量の揺れを抑え、出力時刻・サンプル数・遅延の目標を維持します。変換の再開や処理落ちの際には、この引き継ぎ状態をリセットします。

歌枠では「歌枠用設定にする」で、アプリ内で声と伴奏を合成して出力できます。OBSに接続済みでデスクトップ音声がオンの場合は、二重再生を防ぐためにミュートするか確認します。「はい」でOBSのデスクトップ音声をミュートします。歌枠モードを解除すると、Yuiがミュートしたデスクトップ音声だけを元に戻します。

### 声と伴奏のミックス（Windows）

歌枠用設定の「歌枠用設定にする」を有効にし、自分が聴く伴奏の再生先を選びます。声と伴奏をアプリ内で時刻に合わせてステレオに合成し、音声のルートで選んだ出力先へ送ります。初期の待ち時間は500msです。声のゲインと配信用の伴奏ゲインは変換中も調整できます。待ち時間やデバイスを変える場合は変換を停止します。

伴奏はヘッドホンなどへ普段どおり再生し、アプリの出力先にはCABLE Inputなど別のデバイスを選びます。OBSにはCABLE Outputを取り込む音声ソースを指定します。OBSのミキサーで元の伴奏が重複しないように設定します。

選択した再生先の音が伴奏に入ります。変換後の声を同じ再生先へモニターすると二重に取り込むため、OBSのMIX音声ソースは「モニターオフ」にします。変換が出力時刻に間に合わないと、その区間の声は欠けます。後続の声と伴奏は予定の位置で出力します。MIXを開始すると、接続済みのOBSまたは保存済みの接続情報を使い、JOYSOUNDのウィンドウキャプチャやSpoutキャプチャにMIXの待ち時間を反映します。初期値では待ち時間が500msなら映像も500msです。その他の映像は一覧から追加できます。

### OBS連携

OBSの「ツール → WebSocketサーバー設定」を有効にし、YuiVoiceChangerの「歌枠用設定 → OBS連携 → 設定」で接続します。パスワードを保存している場合は、アプリの起動時にOBSへ自動接続します。MIXを開始すると、JOYSOUNDのウィンドウキャプチャやSpoutキャプチャに待ち時間を反映します。追加の映像は「＋ 映像を追加」から指定できます。500msを超える設定は複数のレンダリング遅延フィルターへ分け、停止時に以前の設定へ戻します。OBS録画で映像が音より早いときは「映像のずれ補正」を＋、遅いときは−に調整します。補正は同期対象の映像すべてに適用されます。

OBSのミキサーでは、CABLE Outputなどから完成したMIXを取り込みます。元の伴奏が別ソースから重複して入る場合は、その音声をOBSのミキサーで外してください。


## RVCからモデルを追加

1. RVC v1/v2の推論用`.pth`、または標準入力を持つ`.onnx`を選びます。32k/40k/48k、音高あり／なしに対応します。
2. 学習素材の読み上げ音声などが入ったフォルダを選びます。WAV・FLAC・OGG・MP3を読み、元の素材は変更しません。数分以上の多様な文章を推奨します。
3. GPU確認が通ったら「学習モデルを作成」を押します。条件は対応NVIDIA GPU、VRAM合計8GB以上・空き6GB以上です。実際の所要時間は学習開始後に表示します。
4. RVCで教材音声を生成し、Beatriceの事前学習モデルを微調整します。進捗・残り時間を表示し、中断時にはモデルと学習状態を保存します。「前回の学習を再開」で続きから学習できます。
5. 完了後「作成したモデルを使う」で変換画面へ戻ります。品質は学習素材や元モデルによって変わり、元モデルと同じになる保証はありません。必ず試聴してください。

初回のみ約550MBの共通モデルを固定リビジョンから取得し、重みのSHA256を検証します。ONNXには追加の互換環境を準備します。
通常の変換と学習はPython 3.15.2のままです。ONNX Runtime 1.31.1に3.15用wheelがないため、その実行部分だけPython 3.14.10 / ONNX Runtime GPUの別プロセスを使います。
学習結果は`%USERPROFILE%\.YuiVoiceChanger\models\<ID>\model.pt.gz`、ログは同じフォルダの`training.log`です。元のモデルや他の学習結果を上書きしません。
独自改造されたRVCや、構造・入出力情報を判別できないONNXは、理由を表示して停止します。任意のONNXグラフに対応する汎用コンバーターではありません。

## 音質と出力タイミング

FP32で生成し、推論時のattention dropoutを無効にしています。3.2秒の過去窓を80msごとに再計算し、波形の整列と20msのクロスフェードでつなぎます。
GPUでは80ms更新・160ms先への予約を使用します。CPUではウォームアップで処理速度を測り、80〜640msの更新間隔とその2倍の出力待ち時間を選びます。実行中はその時刻を維持します。
締切に間に合わない部分は破棄し、後続の音声をずらしません。処理や入出力が追いつかない場合に画面で知らせます。CPUでは総遅延が長くなる場合があります。

通常モードの160msはマイクから出力までの総遅延ではありません。モデルの先読み、波形整列（探索幅10ms）、音声デバイスの遅延が加わります。歌枠用の固定遅延を有効にした場合は、上記の目標に合わせて出力を予約し、整列位置も固定します。
画面の「入力→出力の遅延（目安）」は、出力予約時間・モデル出力の切り出し位置・波形整列・デバイスの申告遅延から計算します。推論時間や音声ブロックの収集は出力予約時間内に行うため、さらに足すと二重計上になります。
この値は音声を戻して測った実測値ではありません。モデルの音響的な時間ずれや機器の申告誤差、OBS・通話アプリ以降の遅延は保証できません。配信の伴奏を厳密に合わせるときは、実際の出力を録音して確認してください。
歌配信では、自分用の伴奏を遅らせず、配信用の伴奏だけを実測した声の遅延に合わせます。自分が聴く変換後の声の遅れは別の問題です。

## 旧VST版からの移行

旧設定は`desktop-before-direct-gpu.json`に一度だけ退避します。マイク・出力先・音高・フォルマントを引き継ぎます。0.3系から移行する際はモデルとPythonを選び直します（`.toml`も新エンジンで使用できます）。
旧版のゲインやEQ・ゲート設定は引き継ぎません。今回の直接生成に合わせ、入力+12dB／出力0dBから始めます。旧ランタイムとモデルファイルは削除しません。

## 開発と確認

バージョン番号は「年.月日.その日の連番」です。例：`2026.1103.1`は2026年11月3日の1版目で、同日の次の版は`2026.1103.2`、別日は連番を1に戻します。月日の先頭のゼロは省きます（1月3日なら`103`）。`npm version 2026.1103.1 --no-git-tag-version`のように指定し、アプリ・インストーラーとも同じ番号を使います。

Node.js 22以降、Python 3.15.2以降の3.15系を使用します。

```powershell
npm ci
npm start
```

アプリ内で環境をセットアップするか、Python 3.15の仮想環境に`requirements.txt`をインストールします。

```powershell
npm run build
npm run test:config
npm run test:ui
python tests/run.py
python tests/gpu_inference.py --checkpoint "voice.pt.gz" --audio "original-48k.wav"
```

`tests/gpu_inference.py`は既存の録音だけを使い、マイクを開きません。任意の`--reference-dir`で試作版との波形一致を確認できます。
実機マイクの開始・停止・再開は`node tests/desktop-audio.cjs <desktop.json>`、初回ダウンロードを含むセットアップは`node tests/runtime-setup.cjs`で明示的に実行します。

`npm run dist`でWindowsインストーラーを作成します。Python、ライブラリ、学習済みの重みは同梱せず、モデル定義とそのライセンスを同梱します。
Apple Silicon Mac試用版はMac上で`npm run dist:mac`を実行するとDMGを作成します。GitHub Actionsの「Apple Silicon build」からもビルドできます。Mac版はCPU推論に対応し、Core Audioを使います。Apple Developer IDによる署名・公証は行っていません。

## 構成

- `backend/`: GPU/CPUモデル定義、推論、モデル読み込み、学習、音声入出力、時刻指定の出力バッファ
- `electron/`: デスクトップ、設定、専用環境のセットアップ、ローカルIPC
- `src/`: React画面
- `drivers/`: 任意の仮想マイクの実験用ソース。通常起動ではインストールしません。
