# モデルと実行環境の設定

変換画面には「入力→出力の遅延（目安）」を表示します。固定の出力予約時間、モデル出力の切り出し位置と波形整列、音声デバイスが申告した入出力遅延の合計です。推論やブロック収集は出力予約時間内に行うため重ねて加算しません。音声を戻して測った実測値ではなく、モデルの音響的な時間ずれや機器の申告誤差、OBS・通話アプリ以降の遅延を保証する値ではありません。停止中は数値を表示しません。

## 読み込めるモデル

| ファイル | 動作 |
| --- | --- |
| Beatrice `.pt.gz` / `.pt` | 学習チェックポイントをGPU/CPUで直接変換 |
| Beatrice `.toml` + 5つの`.bin` | rc.0のFP16書き出し済みの重みを読み、FP32で直接変換 |
| Beatrice `.bin` | 同じフォルダの1つの`.toml`を探す。複数あるときは`.toml`を選択 |
| RVC `.pth` | v1/v2標準形式を識別し、学習画面へ進む |
| RVC `.onnx` | 標準のRVC入出力を識別し、学習画面へ進む |

Beatriceは2.0.0-rc.0系の標準構造に対応します。必要な`.bin`はphone_extractor、pitch_estimator、waveform_generator、speaker_embeddings、embedding_setterです。
通常のモデル選択では声ID 0を使用します。「規約に同意してつくよみちゃんを導入」ボタンでは、公式モデルの声ID 1（コーパス）を一覧に追加し、「このモデルに切り替える」で確定します。
公式モデルは同梱せず、ボタンを押した利用者のPCで公式配布元から取得します。公式規約へのリンクとクレジットはモデル一覧に表示します。配布ファイルと展開後の構成ファイルのSHA256を確認し、元のREADMEと画像も保持します。
RVCは256次元／768次元のContentVec、32k／40k／48k、音高あり／なしに対応します。独自構造や判別できない入力は理由を表示します。
RVCの`.pth`には推論用の`config`と`weight`が必要です。Pythonの重みは`torch.load(weights_only=True)`で読みます。
ONNXの出力サンプルレートはmetadata.samplingRate等を読み、ない場合は標準vocoderのアップサンプリング構造から判別します。判別できない場合はメタデータ付きの書き出しが必要です。

## GPUとCPUの自動選択

初期値は「推奨」です。推奨欄には実行先の型番を表示します。対応NVIDIA GPUで実演算が通ればGPU、使えなければCPUを選びます。環境設定ではCPUと各GPUの型番を一覧表示し、ラジオボタンで実行先を選択できます。GPUが複数あるときは個別に選べます。手動指定したGPUを利用できない場合はエラーにし、別のGPUへ勝手に切り替えません。非対応GPUは理由付きで選択不可にします。変更は次の変換開始時に反映します。
GPUは80ms更新・160msの出力予約、CPUは開始時の測定で更新間隔80〜640msとその2倍の出力待ち時間を選択します。
これらは通常モードの予約時間で、総遅延ではありません。モデル、波形整列、デバイスの遅延が別途加わります。「歌枠用設定」の固定遅延を有効にすると、目標200〜2000msからモデルとデバイスの申告遅延を差し引いて予約し、波形整列位置も固定します。必要な処理余裕より短い場合は開始時に必要値を表示します。どちらも遅れた部分を破棄し、後続の時刻はずらしません。配信用伴奏は実測した声の遅延に合わせて設定します。詳細とエフェクトの説明は[使い方](../README.md#歌枠用設定)を参照してください。
CPUで処理時間が更新間隔を超え続ける場合は、そのPCでは安定動作に十分な処理速度がありません。締切超過・入力落ちを確認してください。

## OBS連携

OBSの伴奏同期は「歌枠用設定 → OBS連携」で設定できます。このPCのOBSへWebSocketで接続し、伴奏ソースを選んで自動設定を有効にすると、変換開始時に「固定遅延＋補正値」を反映します。補正は通常0msで使い、録音で差があった場合だけ調整します。[接続手順と保存・復元の動作](../README.md#obs連携)も参照してください。

## RVCから学習する

「モデル一覧」の「RVCから作成」でRVCモデルと音声素材フォルダを選びます。元のモデルや素材は変更しません。
GPU条件はVRAM合計8GB以上・空き6GB以上です。CPUのみの環境では学習できませんが、完成したモデルの変換は可能です。
初回は約550MBの共通モデルを取得します。RVCで音声を生成後、Beatriceの事前学習モデルをGAN・スペクトル・音量の損失で微調整します。
素材が10ファイル以上なら10ファイルごとに1つを学習対象から外します。品質のため、数分以上の多様な文章の録音を推奨します。
教材の音高はRVC側の変換値、変換画面の音高は作成後のライブ変換値で、別の設定です。
学習回数は2,000／10,000／20,000から選べます。途中のモデルは500ステップごとと中断時に保存し、学習の状態も保存します。
「保存して中断」は現在の処理の区切りで保存します。再開時は生成済み教材とoptimizer状態を利用します。
元のモデルや素材を変更した場合は、別の学習を開始してください。生成した音が元RVCと同じ品質になる保証はありません。

## Pythonと依存関係

変換・学習の本体はPython 3.15.2、PyTorch 2.15.0、TorchAudio 2.11.1です。
ONNX Runtimeの3.15向けwheelがないため、ONNX実行だけPython 3.14.10の専用プロセスを使い、共通音声モデルとBeatrice学習は3.15で動かします。
専用環境は個人設定フォルダに作り、Windows全体のPython、PATH、GPUドライバーは変更しません。

## 保存先

`%USERPROFILE%\.YuiVoiceChanger\desktop.json`：設定。
`models\<ID>\model.pt.gz`：学習済みモデル。
`models\<ID>\training-state.pt.gz`：再開用の学習状態。
`models\<ID>\training.log`：学習ログ。
`models\<ID>\teacher\`：生成した教材音声。
`logs\independent-engine.log`：ライブ変換のログ。

学習中にアプリを閉じた場合も中断を要求します。強制終了や停電の場合は最後の保存地点からの再開です。
